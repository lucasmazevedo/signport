## Additional defects found while fixing
1. **Prepare/cleanup race (REV-07)** — described above; fixed and covered by a regression test.
2. **Connection leak** when the database cannot be configured (for example, a corrupted file): `_connect()` now closes the connection on failure.
3. **Nonce reservation cost under contention:** one transaction per envelope took about 11 ms (fsync and checkpoint), and four contending processes timed out. Reservation now happens in durable blocks of 64, without weakening the guarantee.

## Mutation checks
Twenty-four targeted mutations were applied one at a time to the new mechanisms. Each one ran against the full suite with `SIGNPORT_REQUIRE_OPENSSL=1`, and the sources were restored byte-for-byte afterwards (checked with `diff -r`).

**First run:** 22 of 24 mutations were detected and 2 survived. Both survivors were real test gaps:
- **N09: RSA check removed from `verify_signed_artifact`.** It survived because the recovery tests also fail on the binding recomputation, so the RSA check was never the only defence under test. The new unit test `test_8_cms_signature_value_is_verified` covers it: the CMS is authentic except for its signature value (a random value, or a signature by another key).
- **N14: no-op guard removed from `replace_sealed`.** It survived because `rewrap()` only selects rows that still need work, so the guard was never reached. The new test `test_rev01_replace_sealed_with_current_values_is_a_no_op` calls it directly.

**After the two tests were added:** all 24 mutations are detected.
